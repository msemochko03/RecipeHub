# ЗАВДАННЯ

## Застосунок

**RecipeHub** — REST API бекенд для зберігання та поширення кулінарних рецептів. Користувачі створюють власні рецепти, керують їх видимістю, переглядають публічні рецепти інших користувачів і зберігають їх в обране. API проєктується як бекенд для майбутнього мобільного застосунку.

**Цільові користувачі:** домашні кулінари, які ведуть особисту колекцію рецептів і діляться нею з іншими; у перспективі — мобільний клієнт (iOS / Android).

**Функціональні вимоги:**

1. Реєстрація та вхід за email і паролем з отриманням JWT-токена.
2. Створення, перегляд, редагування та видалення власних рецептів (інгредієнти, кроки, час приготування, порції).
3. Теги рецептів.
4. Пошук і фільтрація за назвою, тегом та інгредієнтом з пагінацією.
5. Видимість рецепта: приватний або публічний.
6. Стрічка публічних рецептів інших користувачів.
7. Обране: збереження чужих публічних рецептів.
8. Масштабування порцій з перерахунком інгредієнтів.

**Технологічний стек:** Java 21, Spring Boot 3 (Web, Data JPA, Security, Validation), Gradle (Groovy DSL), PostgreSQL 16 у Docker, Flyway, springdoc-openapi, JUnit 5, Mockito, MockMvc, Testcontainers.

Детальні вимоги, архітектурні принципи та беклог розвитку: [docs/app-requirements.md](docs/app-requirements.md).

## Обрана агентна IDE

**Claude Code.** Підтримує всі механізми, потрібні курсу: підключення MCP-серверів (`.mcp.json`) для конектора до бази знань, виконання bash-команд (git, Gradle) у робочій директорії, проєктні інструкції (`CLAUDE.md`), hooks (`PreToolUse` / `PostToolUse`) для технічної реалізації guardrails, кастомні skills і subagents для оркестрації. Працює з CLI, тому не залежить від редактора і поєднується з IntelliJ IDEA.

## Мета harness

Прискорити розробку бекенду RecipeHub засобами Claude Code, зберігаючи контроль розробника над архітектурою. Harness дає агенту знання про поточний стан застосунку та прийняті рішення (код, міграції, база знань в окремому репозиторії через MCP), формалізовані процедури для рутинних задач розробки (генерація модулів і тестів, рев'ю, аналіз збоїв) та обмеження, що захищають кодову базу, схему БД і секрети від помилкових автономних дій.

Детальні вимоги до harness (джерела даних, задачі, guardrails): [docs/harness-requirements.md](docs/harness-requirements.md).

## Цільові задачі агента

1. **Генерація каркасу модуля:** Flyway-міграція, сутність, DTO, репозиторій, сервіс і контролер `/api/v1` за конвенціями проєкту.
2. **Генерація тестів:** unit-тести сервісів і інтеграційні тести ендпоінтів на PostgreSQL (Testcontainers), включно з перевірками доступу.
3. **Рев'ю коду** на відповідність архітектурним правилам і конвенціям API.
4. **Аналіз збоїв збірки та тестів** з пропозицією виправлень.

## Репозиторії проєкту

- **recipehub-vault** — база знань (Obsidian vault), наповнюється з ПР № 2.
